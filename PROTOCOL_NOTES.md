# Протокол: откуда что известно

Яндекс не публикует официальный API для управления Станцией с компа.
Этот файл честно объясняет, откуда взято каждое утверждение о протоколе,
а не просто говорит "я уверен" или "я реконструировал".

## Как на самом деле проверялся протокол

Изначально этот проект был вендоренным Python-кодом из чужого репозитория
без лицензии — от него отказались именно из-за лицензии, не из-за
качества (см. git-историю). После переписывания на Go часть деталей
протокола (в основном форма JSON-тела сценария и структура ответа со
списком устройств) была реконструирована по памяти без возможности
проверить на реальном аккаунте — и в первой версии эта реконструкция
оказалась **неверной**: аккаунт с реальными колонками возвращал "не
найдено ни одной колонки", потому что код искал устройства не в том
поле JSON.

Чтобы это починить, я свою прежнюю копию того самого стороннего
Python-репозитория (она осталась в рабочей директории с более ранних
шагов этой сессии) использовал как референс: посмотрел, какие именно
поля и структуры JSON он реально отправляет и парсит, и переписал
Go-код так, чтобы он производил и понимал те же самые JSON-структуры.
Это не копирование кода — ни один Go-файл не содержит транслитерированного
Python, структуры/имена/архитектура полностью свои — но конкретные имена
JSON-полей и форма протокола (`"trigger"`, `"scenarios.steps.actions.v2"`,
`"households"[].all`, `"devices.capabilities.quasar"` и т.п.) взяты именно
оттуда, а не придуманы заново. Формат данных, необходимый для совместимости
с чужим сервером, сам по себе не объект авторского права (это факт
интерфейса, а не творческое выражение) — в отличие от исходного кода,
который я по-прежнему не копирую и не публикую.

Итого: то, что раньше в этом файле было промаркировано как "уверенно
верно" на основе общих знаний о протоколе, теперь либо подтверждено
именно так (сверкой с реальным клиентом), либо всё ещё помечено как
неподтверждённое явно, без общих слов "я уверен".

## Подтверждено сверкой с рабочим клиентом

- **QR-логин**: `passport.yandex.ru/pwl-yandex` -> CSRF из HTML ->
  `.../api/passport/auth/password/submit` -> `.../auth/magic/code` даёт
  `link` для QR -> поллинг `.../auth/magic/code/status` до
  `state == "otp_auth_finished"` -> `.../sessions/get_session` закрепляет
  сессионные куки.
- **Куки -> OAuth x-token**: `POST
  https://mobileproxy.passport.yandex.net/1/bundle/oauth/token_by_sessionid`
  с `client_id`/`client_secret` (публичные ID мобильного клиента Яндекса,
  не секрет конкретного аккаунта) и заголовками
  `Ya-Client-Host`/`Ya-Client-Cookie`.
- **Проверка токена**: `GET
  https://mobileproxy.passport.yandex.net/1/bundle/account/short_info/`
  с `Authorization: OAuth <x_token>`.
- **CSRF для iot.quasar.yandex.ru**: сначала `GET
  https://yandex.ru/quasar`, вытащить `"csrfToken2":"..."` из HTML,
  слать заголовком `x-csrf-token` на все не-GET запросы; при 403 токен
  протух, брать заново.
- **Список устройств**: `GET https://iot.quasar.yandex.ru/m/v3/user/devices`
  -> `{"status":"ok","households":[{"name":..., "all":[...устройства...]}]}`
  — устройства лежат плоским списком под ключом `"all"` внутри каждого
  households, без вложенности по комнатам. У колонок есть `quasar_info`
  с `device_id`/`platform`, и непустой список `capabilities` (без него
  устройство не управляемо, даже если похоже на колонку).
- **Список сценариев**: `GET https://iot.quasar.yandex.ru/m/user/scenarios`;
  создание — `POST .../m/v4/user/scenarios` (ответ содержит id как
  `"scenario_id"` на верхнем уровне); правка — `PUT
  .../m/v4/user/scenarios/{id}`; ручной запуск без произнесения фразы —
  `POST .../m/user/scenarios/{id}/actions`.
- **Форма триггера сценария**:
  `{"trigger": {"type": "scenario.trigger.voice", "value": "<фраза>"}}`
  — именно с вложенным ключом `"trigger"`, значение фразы — плоская
  строка.
- **Форма шага сценария**: тип `"scenarios.steps.actions.v2"`,
  `parameters.items[]`, каждый item — `{"id", "type":
  "step.action.item.device", "value": {"id", "item_type": "device",
  "capabilities": [...]}}`.
- **TTS-капабилити**: `"devices.capabilities.quasar"`, `instance: "tts"`,
  `value: {"text": "..."}` (объект, не строка).
- **Капабилити голосовой команды**: `"devices.capabilities.quasar.server_action"`,
  `instance: "text_action"`, `value` — плоская строка с текстом команды.
- **encode_uid**: фраза-триггер для скрытого сценария на устройство —
  hex-символы device_id, переведённые посимвольно по фиксированной маске
  `0123456789abcdef-` -> `оеаинтсрвлкмдпуяы`, без дополнительных префиксов.

## Всё ещё не подтверждено на реальном железе

- **Glagol (`internal/glagol`)**: токен через `quasar.yandex.net/glagol/token`
  и сам факт локального WSS с самоподписанным сертификатом — в этом
  уверен. А вот форма самого сообщения (`conversationToken`/`id`/
  `sentTime`/`payload.command: "sendText"`) и то, что отдельной команды
  на "чистый TTS" в локальном протоколе, похоже, не существует — это
  по-прежнему не проверено на реальной колонке, у сверенного референса
  локального протокола не было вообще (только облачный). Если `/say`
  через Glagol поведёт себя не так, как ожидаешь — смотри сюда в первую
  очередь.
- Всё остальное (планировщик, диспетчер команд, очередь, HTTP-сервер,
  скрипты) не завязано на детали протокола Яндекса и полностью
  покрыто тестами — при проблемах смотреть нужно именно
  `internal/quasar` и `internal/glagol`, не остальной код.
